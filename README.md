# Technical Writing Portfolio

Documentation samples by **Kumar Gaurav**, a senior technical writer. All organisations, products and figures are fictional and created for portfolio purposes. Vaultline, a fictional key management service, is the product behind samples 2 to 5, so you can see how the pieces fit together.

## Samples

| # | Sample | Type | What it shows |
| --- | --- | --- | --- |
| 1 | [Cryptography Standard](01-cryptography-standard/cryptography-standard.md) | Security standard | Turning ISO 27001, PCI DSS, Australian Privacy Principles and ASD ISM requirements into clear, enforceable rules, with a key-compromise procedure |
| 2 | [Envelope Encryption guide](02-envelope-encryption-api-guide/envelope-encryption-guide.md) | Developer tutorial and API reference | A tested, step-by-step tutorial with Python and curl examples, error codes, troubleshooting and release notes |
| 3 | [Documentation strategy and content audit](03-documentation-strategy-and-content-audit/documentation-strategy.md) | Strategy | Auditing a 24-page doc set with a scoring method, ranking fixes by impact, and a 20-week roadmap with success measures. Includes the [content inventory](03-documentation-strategy-and-content-audit/content-inventory.csv) |
| 4 | [Style guide and templates](04-style-guide-and-templates/style-guide.md) | Standards | A working style guide, terminology list, review checklist and five page templates (tutorial, how-to, API reference, troubleshooting, release notes) |
| 5 | [API reference from an OpenAPI spec](05-api-reference-openapi/api-reference.md) | Docs as code | An OpenAPI 3.0 spec and a Python script that generates the reference, so the docs stay in step with the API |

## Skills demonstrated

- **Documentation strategy:** auditing content, setting priorities, planning a roadmap and defining measures of success
- **Standards and governance:** style guides, templates, terminology control, ownership and review cycles
- **Docs as code:** OpenAPI, Markdown, Python automation and a build you can run in CI
- **Developer documentation:** tutorials, how-to guides, API references, error handling and release notes
- **Security and compliance writing:** turning ISO/IEC 27001:2022, PCI DSS v4.0, Australian Privacy Principles and the ASD ISM into usable requirements
- **Writing for mixed audiences:** developers, system owners, security staff and executives
